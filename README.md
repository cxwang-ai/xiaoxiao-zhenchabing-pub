# 小小侦察兵：长征路上的自然天险

赛道与方向：**数智交互 · 历史回望【险阻解码】**。

扮演虚构的普通红军侦察兵，探索激流、雪山和沼泽的自然规律，再用组合决策带领队伍前行。

## 运行方式

1. 在线体验：**【待填写：部署后的公网链接】**。
2. 离线体验：解压 `xiaoxiao-zhenchabing-offline.zip`，双击其中的 `index.html`；保留同目录的 `css/`、`js/`、`assets/`。无需安装软件或启动服务器。

支持 Chrome / Edge / Safari / Firefox 近两年版本，手机与电脑均可操作。手机请在支持 JavaScript 的浏览器中打开解压后的页面，文件管理器的预览可能不支持运行游戏。

无需注册登录，不收集个人信息。游戏使用全部本地资源，不联网、不调用在线接口；在线入口首次打开需联网下载页面。进度仅保存在本机浏览器，浏览器存储不可用时仍可游玩，但不能保存；未结算的关卡刷新后从该关出发资源重新开始。改名与规则更新沿用原存档 key 和版本：已完成关卡保留原结果，未结算尝试按当前规则重启。

史实与观测数据仍有占位，请以“待核实 / 简化模型 / 游戏参数 / 已核实”标签区分。角色与插图为艺术演绎；关卡代表点、抵达大渡河月份和夹金山翻越点海拔已按作者资料核实；代表点不表示完整历史行军路线。详见 [科学依据与游戏规则](科学依据与游戏规则.md)。

### 打不开怎么办

如果页面显示加载提示或只有几行无样式文字，说明浏览器没能读取同一文件夹中的样式和程序文件。

1. 确认解压后的整个文件夹完整，保留 `css/`、`js/`、`assets/`；不要只拷贝 `index.html`，不要在压缩包预览中直接打开。
2. macOS 用户：改用 Safari 打开，或把整个文件夹移到“下载/桌面/文稿”以外的位置（例如“共享”文件夹 `/Users/Shared/`），再用 Chrome 打开。
3. 也可使用上方“在线体验”中的在线链接。

## 怎样操作

- 点击按钮进入关卡，依次完成“看 → 探 → 闯 → 史”，再回总图。大渡河 → 夹金山 → 草地依次解锁。
- 拖动滑块探索气温、气压、流量等变化；点击决策选项并执行方案。滑块也可用键盘方向键调整，Tab 切换焦点。
- 草地先选补给，点击相邻格行进；可切换“探杆试探”确认相邻未走格的隐患。聚焦网格后按方向键按当前模式操作，Enter / 空格选择聚焦格。
- 失败后“重试本关”恢复本关出发资源；三关完成后进入结算，“重新挑战”清空进度从头开始。

## 标准地图与坐标核实

底图为作者于 **2026-10-07** 从自然资源部标准地图服务系统（bzdt.ch.mnr.gov.cn）下载的 **中国地图 1:2200万 16开 无邻国 线划一（南海诸岛以附图表示）**，审图号：**GS(2016)2884号**（图面标注）。本地原图 `assets/map/china.jpg` 为 **3092 × 2365** 像素，底图来源与审图号已核实。

总图按原始比例完整显示，保留南海诸岛附图、图例和审图号；没有裁切、重新保存或滤色。关卡点与标签独立叠加。“放大查看地图”打开原始分辨率的可滚动查看层，可按关闭按钮或 Esc 退出。

三个关卡代表点坐标已核实，来源见 `levels.js`；后续重新标注时须重新核实地点依据。作者双击打开 `index.html` 后，在地址栏末尾加 `?pick=1` 回车，进入总图，点击地图或放大层中的位置，复制提示框内的 `position` 片段替换 `js/data/levels.js` 对应关卡坐标。对照资料核实后，再把 x、y 的 `status` 改为 `verified`；坐标来源填写作者实际核实依据。无 `?pick=1` 时不显示或启用拾取工具。

## 目录与测试

| 路径 | 用途 |
| --- | --- |
| `index.html` | 双击运行的入口 |
| `css/` | 响应式版画风格样式 |
| `js/data/levels.js` | 数据、核验状态与游戏参数 |
| `js/core/`、`js/levels/` | 状态、规则与三关交互 |
| `js/ui/`、`js/screens/`、`js/main.js` | 组件、页面与启动 |
| `assets/img/`、`assets/map/` | 本地插图与已接入的标准地图 |
| `科学依据与游戏规则.md` | 规则、模型、数据核验表 |
| `docs/` | 源码版的设计、作者待办与 AI 记录 |
| `tests/`、`tools/` | 源码版的自测与打包脚本 |
| `dist/` | 生成的离线包，不纳入版本管理 |

开发自测需要 Node.js，在**源码项目根目录**执行：

```sh
sh tests/run.sh
```

此命令检查所有 JS 语法及规则、界面流程。可选的真实浏览器检查需要 Python Playwright 与 Chromium：

```sh
python3 tests/browser.test.py --screenshots /tmp/xianzu-qa
```

打包另需 Python 3，仅使用标准库（不影响双击运行）：

```sh
sh tools/build-offline.sh
```

脚本先运行测试，失败即中止；成功生成 `dist/xiaoxiao-zhenchabing-offline.zip` 并列出内容。离线包仅包含入口、样式、脚本、资源和两份交付文档，不含 `tests/`、`docs/`、`tools/`、`.git`。

## 部署到 GitHub Pages（作者自行操作）

1. 登录自己的 GitHub，创建用于参赛的公开仓库。把离线包解压后的**内容**上传到仓库根目录，确保 `index.html` 在根目录；不要把 zip 当作网页上传。上传前核对匿名要求。
2. 打开仓库 **Settings → Pages**，在 **Build and deployment** 选择 **Deploy from a branch**，选上传所在分支（通常为 `main`）和 **/(root)**，点击 **Save**。
3. 等待部署完成，打开 Pages 页面给出的地址，在手机和电脑上完整游玩一次；将公网地址填回本 README 的占位，再重新打包或上传更新。

无需把任何密钥写进代码。步骤依据 [GitHub 官方发布源说明](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。
